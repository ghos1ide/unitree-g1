# ELN 联调监控使用说明

监控服务使用机器人端口 **8092**；ELN 业务请求仍发送到 **8090**。
机器人本机打开 http://127.0.0.1:8092/，其他电脑打开 `http://机器人可访问的IP:8092/`。
通过 5G 终端访问时，需要单独确认 8092 的映射和访问权限；无需改变 ELN 的任务地址。

## 联调时怎么看

1. 打开页面，确认右上角“实时连接”，没有数据源错误。记录联调开始时间。
2. 让 ELN 按现有协议发送请求。任务号使用双方约定的唯一值。
3. “请求到达”出现对应时间的 POST 路径，说明请求到达了机器人 HTTP 入口并已返回响应。HTTP 4xx/5xx 表示入口返回异常，不代表网络没通。
4. “任务状态”查找约定的 taskId。“已受理”表示进入过执行流程，“已拒绝”表示受理前失败且已保存失败结果。点击记录查看进度、状态和错误信息。
5. “回调投递”查找同一 taskId。“已送达”表示机器人回调获得接收服务认可；仍需 ELN 侧确认任务在其业务系统中正确更新。“待投递”和“重试耗尽”需要检查回调接收端及相关错误。
6. “请求到达”支持按任务号、来源、路径、错误内容、时间和结果筛选，分页查看全部匹配历史。“最新记录”返回最新页；翻阅旧页时固定分页范围，避免新请求插入造成重复或漏看。
7. 选中请求查看处理过程、业务错误码、错误说明、字段校验详情和脱敏后的请求/响应 JSON。关联到任务号时，还显示该任务当前执行结果与最终回调的投递状态。
8. 请求页点击“导出”会下载全部筛选历史及处理阶段（NDJSON），不限当前页；任务/回调页导出当前监控快照。

页面每轮采集后等待 2 秒再次采集，网络或日志读取耗时会增加显示延迟。暂停仅暂停浏览器刷新，不暂停机器人。
历史记录会显示在页面中，请按任务号和完整时间确认本轮联调，不能只看累计数量。

## 数据范围及限制

- 请求来源：`execution/action_runtime_v3/data/http_requests.sqlite3`，由 8090 入口独立写入 SQLite；收到请求后、读取请求体之前即提交“已到达”记录。之后记录请求体读取、转发、收到后端响应及响应准备完成/失败阶段。关闭浏览器、停止监控或重启服务不会删除历史；不设置自动条数或时间清理，需要保证磁盘空间。`GET /health` 也记录，页面默认隐藏，可勾选“健康检查”查看。
- 来源地址可能是转发服务器或网关，不一定是 ELN 原始地址。每条新请求有独立 ID，通过响应头 `X-Request-ID` 返回。支持 401 授权拒绝、404 路径/任务不存在、参数错误、缺少录制、前置条件拒绝、后端连接/超时等诊断。诊断分类依据已记录的处理阶段和后端响应，不猜测机器人未报告的内部步骤。
- 请求页保存脱敏 JSON，请求/响应各最多 32 KiB，超限或非 JSON 只保存省略原因和字节数；不保存认证头、Cookie、URL 查询参数。JSON 中密钥字段及 URL 凭据也脱敏。原请求内容不被改写，日志失败不自动重试机器人请求。
- HTTP 响应准备完成不代表客户端一定收到了响应；HTTP 502 或重启中断时执行结果可能未知，应根据原 taskId 查询。请求 ID 与任务 ID 不同，重复提交不会混成一条日志。业务未受理但已保存失败任务时，任务页标记为“已拒绝”。
- 监控只能看到已经到达机器人 HTTP 入口的请求，不能记录在 5G 网关、网络或 HTTP 解析层就被拦截的流量。若看到“正在等待执行接口”，说明已发起后端请求但尚未记录响应；请求在入口重启时未完成，会标记“请求处理被中断”。
- 历史补录只恢复 journal 中尚可读取的业务访问日志，无法补出当时未记录的请求体、业务错误详情或已轮转丢失的记录。补录记录明确标为“历史访问日志”，不伪装成完整阶段日志。
- 真实接口回调保留 `ACCEPTED`、`RUNNING`、`SUCCEEDED`、`FAILED`，取消以 `FAILED` 回调。最终结果持续重试直至 ELN 以 HTTP 2xx 和整数 `code=0` 确认；中间状态最多尝试 4 次，以免阻塞最终结果。内部查询仍可显示 `CANCELLED`。详见 [回调约定](CALLBACKS.md)。
- 任务来源：`execution/action_runtime_v3/data/production.sqlite3`，显示最近 80 条任务和 120 条回调。统计数量是数据库累计。
- 状态来源：8090 的只读 `GET /health`。监控页面连接正常，不代表机器人已经初始化或允许执行动作。
- 监控不会发出任务、初始化、取消或恢复请求。当前 8090 接入真实执行服务，ELN 下发任务可能触发实际动作，应沿用现场安全流程。
- 页面没有新记录不一定表示网络不通：应同时检查页面错误、任务号、访问日志是否开启以及请求是否已返回。

## 启动

在 `communication/eln_http_demo` 目录执行：

```bash
/home/unitree/.miniconda3/envs/Unitree/bin/python -m deployment.integration_monitor --host 0.0.0.0 --port 8092
```

可用 `--upstream`、`--database`、`--unit` 指定实际数据源。数据库以只读方式打开，文件不存在时不会创建。
`--history-database` 指定持久化请求库；监控只读该库，由 8090 入口负责写入。
启动用户需要拥有数据库读取和 systemd 日志读取权限。
可通过环境变量 `MONITOR_API_KEY` 设置独立监控访问密钥；配置后页面提示输入。此密钥与 ELN 业务接口密钥无关。
默认未设密钥，能访问 8092 的设备可以读取监控信息。URL 凭据、查询参数和常见密钥字段会被隐藏，但导出文件仍包含任务业务数据。
此启动方式不配置开机自启；监控停止不影响 8090 的任务服务。

## 开机自启

在机器人本机终端执行一次，按提示输入本机 sudo 密码：

```bash
sudo bash /home/unitree/rh56dfx/workspace/deploy/install_eln_monitor.sh
```

安装脚本将 `deploy/eln_monitor.service` 安装到 systemd，启用开机启动并立即启动
（或重启）8092 监控。仅操作监控服务，不启动或重启 8090、执行器及手部服务。
若 8092 被手动启动的进程占用，脚本会退出，需先确认并关闭该监控进程。

监控以 unitree 用户运行，监听所有网卡的 8092，异常退出后每隔 3 秒重启。
可选环境配置文件为 `/etc/default/rh56dfx-eln-monitor`，其中可以设置 `MONITOR_API_KEY`。
数据源尚未就绪时，页面显示对应错误并继续轮询。

验证与日志：

```bash
systemctl is-enabled eln_monitor.service
systemctl status eln_monitor.service --no-pager
journalctl -u eln_monitor.service -n 50 --no-pager
```

应显示 `enabled` 和 `active (running)`；随后访问 `http://127.0.0.1:8092/`。
局域网访问使用机器人实际 IP 和端口 8092；通过 5G 访问仍需单独配置该端口映射。

## 历史补录与查询接口

在 `communication/eln_http_demo` 目录运行以下命令，可重复执行，不会重复导入同一系统日志：

```bash
.venv/bin/python -m deployment.request_history --import-journal eln_interface.service
```

新日志启用后的 journal 副本不重复导入。若系统此前使用易失 journal，重启前的日志可能已丢失。
只读接口为 `GET /requests`、`GET /requests/{request_id}`、`GET /requests/export`；
支持 `search,result,since,until,show_health,anchor`，列表另支持 `page,page_size`（最多 200）。
时间建议使用带时区的 ISO 8601。配置 `MONITOR_API_KEY` 时这些接口同样需要鉴权。
正常运行时只需重启 HTTP 入口与监控加载日志功能，不需要重启执行器或手部服务。
