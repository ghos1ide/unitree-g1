# ELN V1.5 仿真

## 在电脑上体验

1. 双击 `start_demo.bat`，等到显示“就绪”。
2. 点击“运行全部示例”。程序自动执行初始化、前轮转弯、空中/地面 WOW，以及三种起落架示例。
3. 查看进度条下的动作阶段和回调表。最终显示“完成，全部状态回调已送达”。

固定使用本机 Conda `unitree` 环境，无需手动激活。全部动作都是仿真，不驱动真实机器人。

## 单独测试

| 任务 | 窗口参数 | 计数规则 |
| --- | --- | --- |
| 前轮转弯循环 | 完整操作次数 | 左旋一次＋右旋一次，才加 1 |
| 前起落架 WOW | 空中 AIR / 地面 GROUND | 确认目标 WOW 信号后为 1 |
| 起落架连续收放 | 次数、预动作、循环模式 | 按对应锁位确认条件计数 |

起落架选“完整收放循环”时，每次收起确认上位锁，再放下确认下位锁，最终停在下位。
选“最后一次仅收起”时，前 count-1 次完整收放，最后一次确认上位锁后结束，不再放下。
选“先放下并确认下位锁”时，先完成预动作再开始计数，预动作不占用次数。

点“执行所选任务”即可。未初始化时会自动先初始化。执行中点“取消当前任务”，未完成的当前循环不计数；窗口关闭时也会请求受控停止。

## 故障仿真

选择“仿真场景”，再执行单个任务：

- WOW 信号未到位：WOW 任务 FAILED，progress=0。
- 上位锁未确认：收起后失败，不继续放下，当前循环不计数。
- 下位锁未确认：放下后失败，当前循环不计数；预动作失败则不开始正式循环。
- 安全联锁触发：返回错误码 2002，停止后续动作。
- 执行机构故障：返回错误码 2004，保留之前完整完成的次数。

“第几次匹配阶段触发”按每个任务单独计数。例如无预动作、完整收放 3 次，选择“下位锁未确认”、触发次数 2，则第二次下位锁确认失败，最终 progress=1。故障与任务不匹配时不会触发。

失败后选回“正常”再执行，程序会重新初始化。“运行全部示例”固定运行正常场景。

## 连接机器人

机器人必须先升级为 V1.5。旧版 Action 字段不兼容，不能只更新电脑窗口。
机器人在线时，在本机项目目录运行：

```powershell
conda activate unitree
python -m deployment.deploy_robot_demo
python -m deployment.verify_robot_demo
```

升级复用机器人现有 `Unitree` 环境，不创建环境。保留旧任务和配置，备份旧程序并重新编译 ROS2 接口。升级检查到活动任务会停止升级。

升级成功后双击 `start_robot_demo.bat`。机器人地址为 `192.168.0.249`，网关端口 18000；回调经 SSH 返回电脑。当前只是机器人上两个进程间的 ROS2 假动作通信，不接硬件控制。

机器人项目位置：

```text
/home/unitree/rh56dfx/workspace/communication/eln_http_demo
```

机器人重启后，在该目录的两个 SSH 终端分别执行：

```bash
bash deployment/start_fake_controller.sh
bash deployment/start_ros2_gateway.sh
```

查看机器人侧通信：

```bash
cd /home/unitree/rh56dfx/workspace/communication/eln_http_demo
tail -f data/controller.log
```

## 接口变化

初始化必须携带 taskId 和 callbackUrl，并使用 `/api/v1/robot/initialize`。
任务请求改为 NWS_CYCLE、NLG_WOW_OPERATION、GEAR_OPERATION；不再接受旧任务类型和起落架 action 参数。
2003 表示初始化未完成；2004 表示执行机构或信号确认故障。协议未定义任务不存在的业务码，本实现用 HTTP 404＋1001。

完整接口和部署说明见 [README.md](README.md)，协议原文见 [V1.5 接口文档](docs/ELN_HTTP_API_V1.5.html)。
