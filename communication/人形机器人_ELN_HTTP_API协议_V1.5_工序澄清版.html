人形机器人与 ELN 基本控制 HTTP 接口协议

协议版本：V1.5 · 工序澄清版

依据原 V1.5 文档及现场工序160、190、200、250、270、290整理。仅重组和澄清说明，接口路径、HTTP 方法、字段名称与类型、枚举值、错误码和原有计数规则保持不变。

1. 通信与接口总览

项目约定
通信方式HTTP/HTTPS + JSON；全部业务接口使用 POST。
调用方向ELN 向机器人下发任务；机器人向 ELN 回调任务状态。
机器人服务地址https://{robot-host}/api/v1。下表路径已包含 /api/v1，拼接完整 URL 时不要重复添加。
回调地址由 ELN 在请求的 callbackUrl 中提供。
请求头与编码Content-Type: application/json；UTF-8。
时间格式ISO 8601，包含时区，例如 2026-09-20T17:00:00+08:00。
用途调用方向方法与路径
机器人初始化ELN → 机器人POST /api/v1/robot/initialize
下发控制任务ELN → 机器人POST /api/v1/tasks
上报任务状态机器人 → ELNPOST {callbackUrl}
查询任务ELN → 机器人POST /api/v1/tasks/{taskId}/query
取消任务ELN → 机器人POST /api/v1/tasks/{taskId}/cancel
接收与完成是两个不同阶段。同步响应中的 code=0、status=ACCEPTED 只表示任务已接收。动作是否成功完成，以后续任务状态为准；progress 表示已完成次数，不是百分比。

3. 机器人初始化接口

POST /api/v1/robot/initialize

ELN 在执行控制任务前调用，使机器人完成基础自检、执行机构回零和控制系统准备。

3.1 请求示例

{
  "taskId": "INIT-20260920-0001",
  "callbackUrl": "https://eln-host/eln/api/v1/robot-callbacks/task-status"
}

taskId 为初始化任务号，callbackUrl 为状态回调地址。初始化使用专用接口；原请求示例不包含 taskType 或 parameters。

3.2 接收响应与完成判定

{
  "code": 0,
  "message": "accepted",
  "taskId": "INIT-20260920-0001",
  "status": "ACCEPTED"
}

初始化状态通过第5章的统一回调上报，回调中的 taskType 固定为 ROBOT_INITIALIZE。开始时 progress=0，成功完成时 progress=1、status=SUCCEEDED。收到接收响应不代表初始化已经完成。

4. 控制任务下发与参数

POST /api/v1/tasks

4.1 通用请求与接收响应

字段类型必填说明
taskIdstring是ELN 生成的唯一任务号；相同 taskId 不得重复执行。
taskTypestring是NWS_CYCLE、NLG_WOW_OPERATION 或 GEAR_OPERATION。
callbackUrlstring是机器人上报状态的 ELN 地址。
parametersobject是对应任务类型的参数，见4.2至4.4节。

下列各任务示例均为完整请求体。机器人接收任务后的同步响应示例：

{
  "code": 0,
  "message": "accepted",
  "taskId": "TASK-20260920-0001",
  "status": "ACCEPTED"
}

响应中的 taskId 对应本次请求；该响应不表示动作已经完成。

4.2 前轮转弯连续动作：NWS_CYCLE

适用工序：160、290。机器人按照本地预设的全行程动作曲线连续执行。

参数类型取值与含义
countinteger需要完成的前轮转弯操作次数，必须为正整数。
{
  "taskId": "TASK-20260920-0001",
  "taskType": "NWS_CYCLE",
  "callbackUrl": "https://eln-host/eln/api/v1/robot-callbacks/task-status",
  "parameters": {
    "count": 20
  }
}

此示例可用于工序160；工序290使用同一参数结构和 count=20，但需换用新的唯一任务号。

1次＝左旋一次＋右旋一次。只有两个方向均完成，progress 才加1。仅完成左旋或右旋不计为完整操作。count=20 表示20组，即20次左旋和20次右旋。

例如：第1组只完成左旋时 progress=0；第1组右旋也完成后为1；第20组完成后为20，正常完成上报 SUCCEEDED。原协议未规定任务结束后的额外回中动作。

4.3 前起落架承重与 WOW 信号模拟：NLG_WOW_OPERATION

参数类型取值与含义
wowSignalstringAIR：目标为空中状态；GROUND：目标为地面状态。

工序190：进入承重，模拟空中状态

前置条件为系统稳定。按现场工序放下前起落架顶起、进入承重，并模拟起落架及刹车系统 WOW 为空中状态。

{
  "taskId": "TASK-20260920-0002",
  "taskType": "NLG_WOW_OPERATION",
  "callbackUrl": "https://eln-host/eln/api/v1/robot-callbacks/task-status",
  "parameters": {
    "wowSignal": "AIR"
  }
}

工序270：解除承重，模拟地面状态

按现场工序升起前起落架顶起、解除承重，并模拟起落架及刹车 WOW 为地面状态。

{
  "taskId": "TASK-20260920-0003",
  "taskType": "NLG_WOW_OPERATION",
  "callbackUrl": "https://eln-host/eln/api/v1/robot-callbacks/task-status",
  "parameters": {
    "wowSignal": "GROUND"
  }
}

两种任务均在开始时上报 progress=0；WOW 信号达到目标状态后，完成计数更新为1。未达到目标不得上报成功。工序涉及起落架及刹车系统的 WOW 模拟，原协议通过同一个 wowSignal 表达目标，未分别设置两个请求字段。

4.4 起落架连续收放：GEAR_OPERATION

参数类型取值与含义
countinteger需要完成的起落架操作次数，必须为正整数；按 cycleMode 对应的完成条件计数。
preActionstringNONE：无预动作。
EXTEND_DOWNLOCK：正式计数前先放下并确认下位锁上锁；该预动作不计数。
cycleModestringFULL_CYCLE：每次完整收起再放下，最终下位锁上锁。
FINAL_RETRACT_ONLY：前 count−1 次完整收放，最后一次仅收起，最终上位锁上锁。

“收起完成”指确认上位锁上锁；“放下完成”指确认下位锁上锁。发出控制命令、机构开始运动或到达位置但未确认锁定，都不能替代对应阶段的完成确认。

工序200：前4次完整收放，第5次仅收起

{
  "taskId": "TASK-20260920-0005",
  "taskType": "GEAR_OPERATION",
  "callbackUrl": "https://eln-host/eln/api/v1/robot-callbacks/task-status",
  "parameters": {
    "count": 5,
    "preAction": "NONE",
    "cycleMode": "FINAL_RETRACT_ONLY"
  }
}
阶段执行动作与确认条件完成后的 progress
第1至4次每次收起并确认上位锁，再放下并确认下位锁；每完成一整次才计数。依次为1、2、3、4
第5次仅收起，确认上位锁上锁后计数；到此结束，不再放下。5
最终状态：收起且上位锁上锁。该工序共有5次收起、4次放下。progress=5 表示按此模式完成5次操作，不表示完成5次完整收放。不得先完整收放5次后再额外收起。

工序250：先放下，再完整收放5次

{
  "taskId": "TASK-20260920-0006",
  "taskType": "GEAR_OPERATION",
  "callbackUrl": "https://eln-host/eln/api/v1/robot-callbacks/task-status",
  "parameters": {
    "count": 5,
    "preAction": "EXTEND_DOWNLOCK",
    "cycleMode": "FULL_CYCLE"
  }
}
阶段执行动作与确认条件完成后的 progress
预动作先放下起落架，确认下位锁上锁后才能进入正式循环；不计入5次。0
第1至4次每次收起并确认上位锁，再放下并确认下位锁。依次为1、2、3、4
第5次仍执行完整收起、放下；确认下位锁上锁后结束。5
最终状态：放下且下位锁上锁。从收起状态开始时，该工序包含1次预放下＋5次完整收放，共5次收起、6次放下。最开始的预放下不占用 count，也不增加 progress。

原协议通用示例：无预动作，完整收放5次

以下保留原协议的标准完整循环用法。它不包含工序250要求的预放下，不能直接替代工序250参数。

{
  "taskId": "TASK-20260920-0004",
  "taskType": "GEAR_OPERATION",
  "callbackUrl": "https://eln-host/eln/api/v1/robot-callbacks/task-status",
  "parameters": {
    "count": 5,
    "preAction": "NONE",
    "cycleMode": "FULL_CYCLE"
  }
}

5. 统一状态回调

POST {callbackUrl}

机器人在任务状态变化或已完成次数变化时，向任务请求提供的 ELN 地址上报。初始化任务与控制任务共用此回调结构。

5.1 回调报文

{
  "taskId": "TASK-20260920-0001",
  "taskType": "NWS_CYCLE",
  "status": "RUNNING",
  "progress": 8,
  "message": "已完成8/20次前轮转弯操作",
  "timestamp": "2026-09-20T17:00:00+08:00",
  "errorCode": null
}
字段类型必填说明
taskIdstring是ELN 下发的任务唯一编号，机器人原样返回。
taskTypestring是对应控制任务类型；初始化回调固定为 ROBOT_INITIALIZE。
statusstring是ACCEPTED、RUNNING、SUCCEEDED、FAILED 或 CANCELLED。
progressinteger是已经完成的次数，不是百分比；见5.3节。
messagestring是可读状态说明，建议包含当前动作、已完成次数和总次数。
timestampstring是状态产生时间，ISO 8601 格式且包含时区。
errorCodestring/null是非失败状态为 null；FAILED 时填写业务错误码。

5.2 回调时机与状态流转

  1. 机器人接收任务后，上报 ACCEPTED。
  2. 开始执行时，上报 RUNNING，progress=0。
  3. 按对应任务的计数条件更新 progress，并上报变化。
  4. 正常完成上报 SUCCEEDED；失败上报 FAILED；完成受控取消后上报 CANCELLED。

推荐状态流转：ACCEPTED → RUNNING → SUCCEEDED / FAILED / CANCELLED。三个结束状态均为最终状态，不得回退。

5.3 progress 计数规则

任务／模式增加计数的条件成功完成时的值
ROBOT_INITIALIZE初始化完成；开始为0。1
NWS_CYCLE完成一组“左旋一次＋右旋一次”加1；仅完成其中一个方向不增加。count
NLG_WOW_OPERATIONWOW 信号达到目标状态，计数从0变为1。1
GEAR_OPERATION
FULL_CYCLE		每次完成收起、放下并确认下位锁后加1。count
GEAR_OPERATION
FINAL_RETRACT_ONLY		前 count−1 次按完整循环计数；最后一次仅收起并确认上位锁后加1。count

preAction 不计数。发生 FAILED 或 CANCELLED 时，保留停止前已按相应规则完成的次数，未完成的当前动作不得计数。例如：工序200第5次尚未确认上位锁时停止，progress 保持4；工序250预放下阶段停止，progress 为0。

5.4 ELN 回调应答与去重

{
  "code": 0,
  "message": "received"
}

code=0 表示 ELN 已接收回调。机器人未收到成功应答时可重复发送；ELN 应依据 taskId + status + progress + timestamp 去重。这是回调接收确认，不是新的任务执行请求。

6. 查询与取消

6.1 查询任务

POST /api/v1/tasks/{taskId}/query

查询指定任务的当前状态和已完成次数。路径中的 {taskId} 替换为要查询的任务号。

6.2 取消任务

POST /api/v1/tasks/{taskId}/cancel

请求体示例：

{ "reason": "ELN operator cancelled" }

取消是受控停止请求。机器人无法立即安全停止时，应完成安全停机流程，并通过回调返回最终状态。发出取消请求不代表已经停止；完成受控取消后上报 CANCELLED，并保留已经完成的次数。

原 V1.5 未给出查询接口的请求体和响应体结构，也未给出取消接口的同步响应结构。本版保留该定义边界，不将状态回调报文擅自规定为查询响应。

7. 统一错误码

code说明
0成功或已接收
1001参数错误
1002未授权
1003任务号重复
2001机器人忙
2002安全条件不满足
2003初始化未完成
2004执行机构故障

同步应答使用 code；状态回调使用 errorCode。回调字段仍保持原定义的 string/null 类型，不因本表以数字列示错误码而改成整数。原文未提供失败回调中业务错误码的具体字符串示例及其与本表的映射，本版不新增映射。

8. 安全与执行要求

  • 起落架收起或放下动作，只有确认对应上位锁或下位锁上锁后，才能判定该阶段完成。
  • FINAL_RETRACT_ONLY 的最后一次确认上位锁后必须停止，不得自动继续放下。
  • EXTEND_DOWNLOCK 预动作必须确认下位锁上锁后，才能开始正式计数。
  • NLG_WOW_OPERATION 必须校验 WOW 信号是否达到目标状态；未达到目标不得上报成功。
  • 安全联锁、硬件急停或人员进入危险区域时，机器人应停止后续动作，并按实际已完成次数回调 FAILED 或 CANCELLED。

事项现有定义及待确认范围
