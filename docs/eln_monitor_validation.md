验证时，数据源均无错误：请求日志窗口内 0 条记录，数据库中 2 条历史任务

## 展示语义

- 请求：显示访问日志的响应时间、来源、方法、路径和 HTTP 状态。
- 受理：任务入库记录标为“已受理”；提交和初始化请求仅有访问日志时标为“待核对”；查询等请求标为“不适用”。HTTP 200 不等于业务受理，502 也不能证明未受理。
- 任务：显示真实任务号、参数、状态、进度和错误。
- 回调：显示真实 outbox 投递状态、尝试次数、地址和最近错误。

现有访问日志没有请求体、业务响应码或 taskId，无法逐条关联提交请求与任务，
也无法追溯每次拒绝的业务原因。正在等待响应的请求尚不会出现在访问日志中。
新增明确的受理状态展示，避免把 HTTP 返回结果当作任务受理结果。
修复了原有详情字段函数中导致页面脚本无法解析的括号错误。
